텍스트→수어: 2D 프로토타입 → 언리얼 3D MetaHuman 아바타로 전환

Version 4.0
이 문서의 목적: 실제로 완성된 것과 앞으로 할 것을 정직하게 구분 기록한다. 상태는 완료 / 진행중 / 예정 / 비전으로 표시. 무단 축약·누락 금지.

이번 개정 핵심 (Ver 3.2 → 4.0)

  1. 최종 방향성 변경: 2D 캐릭터 아바타 → 언리얼 MetaHuman(Skye) 기반 실물급 3D 아바타가 메인 트랙으로 승격. 2D는 품질 한계로 폴백 보존.
  2. 데이터 근본 문제 발견 & 해결: AI Hub 좌표는 위치만 있고 회전 좌표가 없음 → 3D 자연스러운 구동 불가. 실제 동영상을 언리얼 마커리스 모캡으로 재처리해 회전 애니메이션 추출(손가락 포함)로 해결.
  3. 수집 아키텍처 = 하이브리드 확정: 인식용(위치) 파이프라인은 유지, 아바타용(회전)은 별도 "회전 데이터 뱅크" 신설.

최종 목표

병원·은행·관공서 창구에서 농인↔직원의 양방향 실시간 소통.

  • [A방향] 수어→텍스트·음성: 웹캠 인식 → 문장 조립 → 음성 출력 (E2E 완성)
  • [B방향] 텍스트→수어 아바타: 타이핑 → 글로스 → 언리얼 3D MetaHuman이 실물처럼 수어 시연
  • 상용화 비전: 실사용자(농인↔일반인) 간 실시간 양방향 커뮤니케이션. 궁극적으로 임의 입력 문장을 3D 아바타가 실시간 수어로 변환.

현재 위치

  • [A방향] 완성 유지. 웹캠 인식(학습단어 98%) → 단어 누적 → 문장 조립(규칙+LLM) → 음성 출력 E2E.
  • [B방향] 방향 전환. 2D 캐릭터는 검증 완료했으나 품질 한계로 메인 제외. 언리얼 5.8 MetaHuman Animator로 실제 영상→회전 애니메이션 추출 파이프라인 검증 완료(WORD1501, 손가락 포함).
  • 다음 관문: ① 회전 데이터 뱅크 포맷 결정 ② 데모 단어 애니메이션 제작 ③ GUI 연결 방식 결정.

예정GUI 연결 방식 확정사전렌더 MP4 vs 실시간 UDP
⚠ 정직한 한계 & 결정 대기:
  • 실시간 UDP의 벽: send_skeleton_ubp.py는 여전히 위치 좌표 전송 → 위치→회전 변환 블루프린트 없으면 고품질 불가. 실시간 마커리스 모캡은 현재 오프라인 전용.
  • 안정성 vs 실시간성: 사전렌더 MP4=최고 품질·안정·손가락 해결(정해진 단어만). 실시간 UDP=임의 입력 가능하나 변환 미완성·손가락 노이즈·프리징 위험.
  • 하드웨어 제약: Skye 로드에 10GB 필요, 가용 8.3GB. 데모 시 무거운 프로그램 종료 필수.

핵심 원칙

  1. 인식용(A방향)은 손대지 않는다. LSTM은 위치 좌표만 있으면 되므로 기존 로직 유지.
  2. 아바타용(B방향)은 회전 데이터 뱅크 신설. 언리얼 모캡 회전값을 단어 단위로 저장.
  3. text_to_gloss가 두 세계의 다리. 문장→글로스 로직 공유, 마지막 재생 단만 3D 교체.
  4. 없는 단어는 "표현 불가" 안내. 회전 뱅크에 없는 단어는 정직하게 처리.

투자 발표 스토리

① 수어→텍스트·음성 완성(웹캠 98%→문장→음성) → ② 텍스트→수어를 2D 프로토타입에서 언리얼 실물급 3D 아바타로 진화(회전 데이터 자체 추출 기술 확보) → ③ 병원·은행 창구 문장 데모 → ④ 실시간 양방향 커뮤니케이션 상용화 + API 라이선스 사업.

경쟁력: 남의 아바타를 재생하는 게 아니라, AI Hub에 없던 회전 데이터를 우리가 직접 모캡으로 추출·구축하고 그 위에 글로스 번역·모션 블렌딩·3D 렌더링 엔진을 자체 개발했다.
